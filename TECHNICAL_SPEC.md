# Технічне завдання: BotLabs Notification Bot

## 1. Загальний опис проєкту

**Назва:** BotLabs Daily Standup Notifier
**Тип:** Telegram-бот для групових сповіщень
**Стек:** Node.js (JavaScript), node-cron, Telegraf (або grammY), SQLite/JSON-файл для зберігання конфігурації
**Деплой:** VPS / Digital Ocean (існуюча інфраструктура BotLabs)

### Мета
Бот додається в робочий Telegram-чат команди BotLabs і автоматично відправляє щоденні сповіщення про стендап-зустрічі за розкладом. Адміністратор (визначений за Telegram username `@deyneka_i`) має повний контроль над текстами, розкладом та налаштуваннями через **інтерактивну кнопкову панель** прямо в боті.

## 2. Функціональні вимоги

### 2.1. Система сповіщень

Бот відправляє повідомлення в групу за фіксованим розкладом **щодня з понеділка по п'ятницю**:

| Час      | Тип            | Зміст за замовчуванням                                                              |
|----------|----------------|-------------------------------------------------------------------------------------|
| 10:00    | Привітання     | "☀️ Продуктивного Вам дня!" + кнопка [Підключитися] з посиланням                    |
| 10:10    | Передостаннє   | "⏰ Стендап через 5 хвилин!" + кнопка [Підключитися] з посиланням                   |
| 10:15    | Старт          | "✅ Стендап почався. Всі на зв'язку!"                                               |
| 17:55    | Нагадування    | "🔔 Вечірній синк через 5 хвилин!" + кнопка [Підключитися] з посиланням             |
| 18:00    | Старт          | "✅ Вечірній синк почався. Всі на зв'язку!"                                         |

**Вимоги до повідомлень:**
- Формат: Telegram Markdown або HTML
- Inline-кнопки (InlineKeyboardMarkup) з URL-посиланням на зустріч
- Можливість вмикати/вимикати кнопку для кожного слота окремо
- Таймзона: Europe/Kyiv (UTC+2 / UTC+3 залежно від DST)

### 2.2. Розклад і cron-система

- Використовувати `node-cron` або `node-schedule`
- Кожен слот сповіщення — окремий cron-запис
- Перевірка дня тижня: тільки Mon–Fri (1–5)
- Підтримка автоматичного переходу літній/зимовий час (Europe/Kyiv)
- При зміні розкладу через адмін-команди — перезапуск відповідних cron-задач без рестарту бота

### 2.3. Адмін-панель (кнопкова, через InlineKeyboard)

Адміністрування відбувається через **приватний чат з ботом** (або в групі). Вся навігація побудована на **InlineKeyboardMarkup** — адмін натискає кнопки, а не вводить команди вручну.

#### Точка входу:
Команда `/admin` або `/start` → бот показує **головне меню** з кнопками:

```
🔧 Панель управління BotLabs Notifier

[📋 Список слотів]     [➕ Додати слот]
[🔗 Змінити посилання]  [⏸ Пауза всіх]
[📡 Прив'язати групу]   [ℹ️ Статус]
```

#### Потік "Список слотів" → керування конкретним слотом:

1. Адмін натискає **[📋 Список слотів]**
2. Бот показує список усіх слотів як кнопки:
```
Оберіть слот для редагування:

[☀️ 10:00 — Привітання  ✅]
[⏰ 10:10 — Передостаннє ✅]
[✅ 10:15 — Старт        ✅]
[🔔 17:55 — Нагадування  ✅]
[✅ 18:00 — Вечірній старт ✅]
[← Назад]
```
> ✅ = увімкнено, ⏸ = вимкнено

3. Адмін натискає на конкретний слот → відкривається **меню слота**:
```
⏰ Слот: morning_greeting (10:00)
Текст: ☀️ Продуктивного Вам дня!
Кнопка: Підключитися → https://meet.google.com/xxx
Статус: ✅ Увімкнено

[✏️ Змінити текст]    [🕐 Змінити час]
[🔗 Змінити посилання] [👁 Превʼю]
[⏸ Вимкнути]          [🗑 Видалити]
[← Назад до списку]
```

4. Натискання **[✏️ Змінити текст]** → бот пише: "Введіть новий текст для слота morning_greeting:" → адмін вводить текст → бот підтверджує кнопками:
```
Новий текст: "🌅 Доброго ранку, команда!"

[✅ Зберегти] [❌ Скасувати]
```

5. Натискання **[🕐 Змінити час]** → бот показує кнопки для швидкого вибору:
```
Оберіть новий час або введіть вручну (HH:MM):

[09:30] [09:45] [10:00] [10:15]
[10:30] [10:45] [11:00] [← Назад]
```
> Або адмін вводить час вручну у форматі HH:MM

#### Потік "Додати слот":
1. **[➕ Додати слот]** → бот запитує час (кнопки + ручне введення)
2. Потім запитує текст повідомлення
3. Потім запитує: "Додати кнопку з посиланням?" → **[Так]** / **[Ні]**
4. Підтвердження:
```
Новий слот:
🕐 13:00 | 🍕 Обідня перерва!
Кнопка: Ні

[✅ Створити] [❌ Скасувати]
```

#### Потік "Змінити посилання":
1. **[🔗 Змінити посилання]** → бот показує:
```
Поточне посилання: https://meet.google.com/xxx

Змінити для:
[🌐 Всіх слотів]
[📌 Конкретного слота]
[← Назад]
```
2. Адмін обирає → вводить нове посилання → підтвердження кнопкою

#### Потік "Пауза всіх":
1. **[⏸ Пауза всіх]** → бот показує:
```
⚠️ Вимкнути ВСІ сповіщення?
Бот перестане відправляти повідомлення в групу.

[⏸ Так, поставити на паузу] [← Скасувати]
```
2. Коли на паузі, кнопка змінюється на **[▶️ Відновити всі]**

#### Резервні текстові команди (працюють паралельно):

| Команда                        | Опис                                                        |
|--------------------------------|-------------------------------------------------------------|
| `/admin`                       | Головне кнопкове меню                                       |
| `/status`                      | Швидкий статус усіх слотів                                  |
| `/setchat`                     | Виконати в групі — бот запам'ятає chat_id                   |
| `/next`                        | (публічна) Наступна зустріч                                 |

### 2.4. Система безпеки та авторизації

- **Жорстка прив'язка до Telegram username** — `ADMIN_USERNAME=deyneka_i` в `.env`
- Додатково зберігається `ADMIN_ID` (числовий ID) як fallback, оскільки username можна змінити
- При першому зверненні адміна бот автоматично зберігає його числовий ID для подвійної перевірки
- Перевірка: `ctx.from.username === process.env.ADMIN_USERNAME` **АБО** `ctx.from.id == storedAdminId`
- Будь-яка адмін-команда / натискання кнопки від стороннього користувача → ігнорується повністю (без відповіді)
- Callback-кнопки адмін-панелі перевіряють `callback_query.from.username` перед обробкою
- Логування всіх спроб неавторизованого доступу (timestamp, user_id, username, дія)
- Бот НЕ реагує на команди звичайних користувачів у групі (окрім `/next` — показати час наступної зустрічі)

## 3. Нефункціональні вимоги

### 3.1. Стабільність
- Автоперезапуск при краші (PM2 або systemd)
- Graceful shutdown з очищенням cron-задач
- Health-check endpoint (опціонально: простий HTTP `/health`)

### 3.2. Логування
- Усі відправлені повідомлення → лог (timestamp, slot_id, chat_id, статус)
- Усі адмін-дії → лог
- Помилки відправки → лог + повідомлення адміну в ЛС
- Формат: JSON-логи через `winston` або `pino`

### 3.3. Відмовостійкість
- Якщо Telegram API повертає помилку при відправці — 3 ретраї з інтервалом 5/15/30 секунд
- Якщо група недоступна (бот кікнутий) — повідомити адміну в ЛС
- Збереження конфігу на диск після кожної зміни (atomic write)

### 3.4. Timezone-aware
- Усі часи в конфігу зберігаються як локальний час (Europe/Kyiv)
- Cron-задачі працюють з урахуванням DST
- Використовувати `luxon` або `date-fns-tz` для роботи з таймзонами

## 6. Сценарії використання

### Сценарій 1: Перший запуск
1. Створити бота через @BotFather → отримати токен
2. Заповнити `.env`
3. `npm install && npm start`
4. Додати бота в групу BotLabs
5. Написати в групі `/setchat` — бот запам'ятає chat_id
6. Бот починає працювати за розкладом

### Сценарій 2: Зміна посилання на зустріч
1. Адмін пише `/admin` → натискає **[🔗 Змінити посилання]**
2. Натискає **[🌐 Всіх слотів]**
3. Вводить нове посилання
4. Натискає **[✅ Зберегти]**

### Сценарій 3: Вимкнення вечірніх нотифікацій на тиждень
1. `/admin` → **[📋 Список слотів]** → **[🔔 17:55]** → **[⏸ Вимкнути]**
2. Повторити для **[✅ 18:00]**
3. Через тиждень — увімкнути назад тим же шляхом (**[▶️ Увімкнути]**)

### Сценарій 4: Стороння людина натискає адмін-кнопку
1. Юзер якось бачить адмін-повідомлення з кнопками
2. Натискає будь-яку кнопку → бот перевіряє `callback_query.from.username`
3. Username ≠ `deyneka_i` → callback ігнорується, `answerCallbackQuery("⛔️ Доступ заборонено")`
4. Запис у лог: `{ "event": "unauthorized_callback", "userId": 555, "username": "hacker", "action": "edit_slot" }`

### Сценарій 5: Додавання нового слота
1. `/admin` → **[➕ Додати слот]**
2. Бот запитує час → адмін обирає кнопкою або вводить `13:00`
3. Бот запитує текст → адмін вводить "🍕 Обідня перерва!"
4. Бот питає **[Додати кнопку?]** → **[Ні]**
5. Підтвердження → **[✅ Створити]**

## 7. Вимоги до деплою

| Параметр         | Значення                              |
|------------------|---------------------------------------|
| Runtime          | Node.js ≥ 18 LTS                      |
| Process manager  | PM2 (`pm2 start ecosystem.config.js`) |
| RAM              | ~50–100 MB                            |
| CPU              | мінімальний (cron + webhook/polling)   |
| Диск             | ~20 MB (код + логи)                   |
| Мережа           | Доступ до api.telegram.org             |

### PM2 ecosystem.config.js
```js
module.exports = {
  apps: [{
    name: 'botlabs-notify',
    script: 'src/index.js',
    instances: 1,
    autorestart: true,
    max_restarts: 10,
    restart_delay: 5000,
    env: {
      NODE_ENV: 'production'
    }
  }]
};
```

## 9. Можливі розширення (v2)

- **Вебхук-режим** замість polling (для продакшн на домені)
- **Веб-панель** (React/Next.js) для візуального адміністрування
- **Інтеграція з Google Calendar** — автоматичне підтягування посилань на зустрічі
- **Підтвердження присутності** — кнопка "Буду" під сповіщенням, бот збирає статистику
- **Святкові дні** — автоматичне вимкнення на державні свята України
- **Мультигрупа** — підтримка декількох груп з різними розкладами
- **Нагадування про невідмічених** — якщо хтось не натиснув "Буду", бот пінгає
